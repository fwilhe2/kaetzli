# Patches

Packages can apply downstream patches and upstream patch series during source extraction.
Patch files are committed under `packages/<pkg>/patches/` and are applied without network
access during the package build.

```text
packages/<pkg>/patches/
├── upstream/             # fetched upstream series, when configured
└── 0001-<topic>.patch    # project patches, applied afterwards in name order
```

Patches are included in the extraction stamp, CI cache key, sources image, and SBOM. The
SBOM records each patch name and SHA-256 in the package comment. Patches apply with
`--fuzz=0`; update a patch when upstream changes the context.

## Project patches

Use a project patch for a fix that is not in the pinned release. Prefer an upstream commit
patch when available. Remove the patch when a pinned release includes the change; otherwise
the package extraction fails when the patch no longer applies.

Patch files use `-p1` paths (`a/` and `b/` prefixes). For example, save an upstream patch
under the package's patch directory:

```sh
curl -fL 'https://git.savannah.gnu.org/cgit/gzip.git/patch/?id=<commit>' \
    -o packages/gzip/patches/0001-<topic>.patch
```

Use `./tools/check-patches.sh <pkg>` to verify that the patch applies to the pinned source.

## Upstream patch series

Some projects publish fixes separately from source releases. Configure the series in the
package's `env.sh`:

```sh
UPSTREAM_PATCHES="https://ftp.fau.de/gnu/bash/${PACKAGE}-patches/"
UPSTREAM_PATCH_REGEX="bash${VERSION//./}-[0-9]{3}"
UPSTREAM_PATCH_STRIP=0
```

`UPSTREAM_PATCH_STRIP` sets the `patch -p` level; the default is `1`. The
`packages/<pkg>/patches/upstream/` directory is generated by `tools/sync-patches.sh`.
Upstream series are append-only: existing files must remain byte-for-byte unchanged, and
new files are added at the end of the series. If upstream signs patches, the package pins
the signing key in `upstream-key.asc` and new patches are verified with `gpgv`; the same
file holds the keys its release tarballs are checked against (`SIG_URL`,
`tools/verify-signature.sh`). Git-based series retain their commit IDs in each patch.

```sh
./tools/sync-patches.sh --list bash   # report the upstream series
./tools/sync-patches.sh bash          # update the committed series
```

`tools/check-updates.py` detects a longer series. The package update workflow opens a pull
request with the new patches and the CVEs they fix. A package version bump starts a new
series.

For a series stored on a server, additional settings include:

```sh
UPSTREAM_PATCH_SIG=".asc"                              # default: .sig
UPSTREAM_PATCH_SKIP="ncurses-6\.6-20251230\.patch\.gz" # already in the tarball
```

Compressed patches are verified in their downloaded form and committed decompressed. Patch
preambles are not run as shell scripts; the build permits only `rm -f` commands for paths
inside the extracted source tree.

### Git release branches

Some projects backport fixes on a release branch. glibc uses:

```sh
UPSTREAM_PATCH_GIT="https://sourceware.org/git/glibc.git"
UPSTREAM_PATCH_BRANCH="release/${VERSION}/master"
UPSTREAM_PATCH_BASE="glibc-${VERSION}"
```

`sync-patches.sh` records commits after the base tag as a format-patch series. A glibc
series update rebuilds all packages because they use the glibc sysroot.

## CVEs fixed by patches

`tools/patch-cves.sh <pkg>` lists CVEs fixed by a package's patches. It reads upstream
advisory data in `patches/upstream.cves` and CVE identifiers in project patch messages, for
example:

```text
CVE: CVE-2026-12345
```

The build records these fixes in the package's SBOM. `test/cve-scan.py` converts them to
OpenVEX statements for grype, so fixed CVEs are reported as patched rather than open. The
CI scan is informational; it does not gate the build.

## Check patches

```sh
./tools/check-patches.sh                       # all packages with patches
./tools/check-patches.sh gzip                  # one package, pinned source
./tools/check-patches.sh --version 1.16 gzip   # an unpinned release
KEEP=1 ./tools/check-patches.sh gzip           # keep the extracted source tree
```

The check extracts the source and applies patches in the builder image. It requires the
source archive and builder image; the first run fetches them. An unpinned `--version` source
is downloaded to `output/patch-check/` without checksum verification. The normal package
build applies patches the same way. A patch change triggers source re-extraction.
