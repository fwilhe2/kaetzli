# How big each assembled image is allowed to be, per flavour and architecture, in MiB.
#
# `test/rootfs-size.py` fails a build that goes over. This is not a measurement and not a
# target — it is a ceiling somebody chose, and the only reason it is in git is so that
# crossing it takes a commit. Nothing else in CI notices an image getting bigger: every
# check here asks whether the image *works*, and a fatter one works fine right up until
# it doesn't fit.
#
# When a build fails against this, exactly one of two things happened:
#
#   - something started shipping files nobody asked for — a package that grew a new data
#     directory, a trim rule in image/build-rootfs.sh that stopped matching after a
#     version bump. The breakdown the script prints says which directory and which files.
#     Take it back out; do not raise the number.
#   - the image genuinely got bigger for a reason you wanted. Raise the number here, in
#     the same commit as the change that needed it, so the diff carries both.
#
# An image with no line here is an image nothing is watching, so that is an error rather
# than a pass: a new flavour or a new architecture has to be given a ceiling before it
# ships, and the check prints the line to add.
#
# The numbers are the size of the assembled tree measured in a real CI build plus about
# 8% of headroom — the disk rows from a build that measured 101.0 MiB on amd64 and
# 152.6 MiB on arm64. Apparent tree size, not blocks used, so they mean the same thing on
# every row; what each image then costs in its own container is reported separately
# (`disk` for the compressed EROFS image, `archive` for the gzipped OCI layer) and is
# not budgeted. The disk rows were `ext4` until the image became EROFS; the tree they
# measure is the same one, so the numbers carried over.
#
# arm64's ceiling is half again amd64's, and the kernel is only 21 MiB of that 51 MiB
# gap: with CONFIG_MODULES off, kconfig resolves arm64 defconfig's many `=m` symbols to
# `y` rather than `n`, so ~40% more is built in — see the vm.config discussion in
# CLAUDE.md. The other 30 MiB is userspace, and most of that is not code but padding.
# The aarch64 linker defaults to 64 KiB pages, so every shared object is aligned to a
# 64 KiB boundary between its LOAD segments; glibc's 253 gconv modules are a few tens of
# KiB of tables each and cost 18.8 MiB on arm64 against 7.7 MiB on amd64. Nothing grew
# there — the same files are simply more expensive to ship on that architecture.
#
# Raised for issue #77, in two steps and for two reasons, both of them "the image
# genuinely got bigger for a reason you wanted":
#
#   +4  iproute2, iputils and libmnl. Measured locally at 2.9 MiB on the disk image and
#       3.7 MiB on the container one, against a tree with them taken back out.
#   +12 openssl, curl and ca-certificates. Measured the same way at 10.6 MiB, identically
#       for both flavours; libcrypto.so.3 alone is 6.8 MiB of it.
#
# The arm64 rows are raised by half again, the same ratio their userspace already stands
# at against amd64's, and for the same reason — see the paragraph below.
#
# Measured on a local tree rather than in CI, so treat the arm64 rows in particular as
# an estimate until a run confirms them. Worth knowing while doing that: repeating an
# image build on the same staging tree is exactly reproducible, but two trees differing
# only in files that were deleted from one produced ~0.9 MiB of difference in
# directories neither touched — image/build-rootfs.sh strips in parallel with
# `xargs -P`, and the batching depends on find's order.
#
# openssh landed without a row moving, and the number is written down here rather than
# left to be rediscovered: measured locally on amd64 it took the ext4 image from 86.9 to
# 95.2 MiB (8.3) and the oci one from 54.3 to 58.5 (4.2 — the client half; the server
# half is subtracted with PAM). Most of that is not the daemon: openssh builds a static
# libssh.a and links it into each of its installed binaries, so `ssh`, `sshd`, `scp`,
# `sftp`, `ssh-keygen`, `ssh-agent`, `ssh-add`, `ssh-keyscan`, `sshd-session`, `sshd-auth`
# and `sftp-server` each carry their own copy of the protocol code. Another 0.66 MiB is
# /etc/ssh/moduli, a data file for a key exchange modern clients no longer negotiate.
# Both are the places to look first if a ceiling ever needs defending rather than raising.
#
# Raised for the container engine, the largest single step this file has taken and the
# one it exists to make deliberate. Measured locally on amd64, stripped: 62.6 MiB, of
# which podman is 44.0 and netavark 10.3; quadlet, aardvark-dns, glib, pcre2, nftables,
# jansson, libseccomp and conmon are the other 8. On top of CI's 93.8 MiB tree that is
# ~156.5 MiB, plus the usual 8% — and CI then measured exactly 156.5 MiB on amd64 and
# 192.6 MiB on arm64, which is where both rows come from. The disk image itself, compressed
# EROFS, went from 59.1 to 94.3 MiB on amd64 and to 96.3 MiB on arm64. The oci rows do not
# move: build-rootfs.sh subtracts the engine from the container image, which measured 59.0
# and 73.1 MiB.
#
# Lowered for the first time, after a pass over what the image carries rather than what it
# needs. Measured locally on amd64: the erofs tree from 160.3 to 143.7 MiB and the oci
# tree from 59.0 to 46.7. coreutils as one multicall binary is 5.2 MiB of that by itself;
# the rest is the Rust helpers built with LTO, e2fsprogs and zstd linking their own shared
# libraries instead of a static copy per tool, and files nothing in the image can reach —
# libdw and libfdisk, unconfigured PAM and NSS modules, bash's loadable builtins,
# iproute2's hardware tools, ssh-agent and /etc/ssh/moduli, D-Bus introspection XML.
# The disk image itself, compressed, went from 96.3 to 61.4 MiB, most of that from
# mkfs.erofs's options rather than from anything removed: see image/build-rootfs.sh.
#
# The amd64 rows are the measurement plus the usual 8%. The arm64 rows are CI's last
# arm64 measurement (186.1 and 73.1 MiB) minus amd64's absolute saving, plus 8%, which
# should be loose: arm64 pads every shared object's segments to 64 KiB, so a hundred
# coreutils binaries becoming one saves more there than here. Tighten them from the
# first CI run's numbers.
#
# flavour  arch   MiB
# Lowered for #192, which made podman a system extension: the disk tree went from 144.0
# to 83.4 MiB on amd64 and to 108.3 MiB on arm64, both measured in CI (run 40090943060),
# and the ceilings to that plus about 8%. The OCI rows are untouched: the container
# flavour never had podman.
#
# Lowered for arm64 by 16 KiB segment alignment (builder/build-package.sh, glibc's
# configparms; systemd keeps the default, for its EFI stubs): measured in CI (run
# 44934567492) the arm64 erofs tree went from 88.2 to 75.4 MiB and the oci tree from 58.8
# to 47.0, level with amd64's 75.0 and 49.1 — the padding the paragraph at the top
# explains is gone. The rows are that plus about 8%.
erofs      amd64  90
erofs      arm64  82
oci        amd64  51
oci        arm64  51
